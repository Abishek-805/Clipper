# Clipper repository and workflow audit

**Baseline** `4bdb693f760b8b49cd7bc6c27ecf8209a2236159` on `main`
**Scope** Daily browser application from import to delivery, shared media and model components, Windows launch, optional Tk/VLC review, queue, and experimental selection code. Checked dependencies, launch and processing behavior, data persistence, existing evaluation evidence, and external clipping/publishing workflows. Historical benchmarks are identified separately from tests run for this audit.

## Start clipping

1. On Windows, run `setup.bat` for a new install or to update dependencies. Install FFmpeg with FFprobe, libx264, and libass if the diagnostic output lists missing tools. In a new PowerShell session, `ffmpeg -version` and `ffprobe -version` should both work with a PATH installation.
2. Run `run.bat`. Choose a local file, inspect tracks, and choose the audio you want. For your first test, record 30–60 seconds on your phone. Pick one complete answer of about 20–45 seconds.
3. Set captions to **None** for the fastest first export. For captions, accept the one-time Whisper download in setup. Then choose **Whisper transcription** (spoken language) or **Whisper translation to English** and check **Transcribe explicitly** to generate a missing transcript.
4. Open **Find a moment and mark my own clip**. Load/search the transcript or enter source seconds. Select a line to fill the interval, adjust both ends, and play **Preview interval**. Include enough context for a new viewer. Create a draft, correct the captions, and click **Save & Re-render Clip**.
5. Play the rendered draft with sound. Check the opening, ending, meaning, names, crop, and whether on-screen text stays readable. Click **Export delivery files**. Confirm publishing rights and any credit requirements before posting.

Clipper processes and exports locally. The first Whisper setup downloads model weights; the workflow has no per-clip fee or artificial export quota. Storage, hardware and processing time determine throughput.

## Findings

| Priority | Area and evidence | Result |
| --- | --- | --- |
| P0 | **Clean-install captions were blocked.** `setup.bat` promised a first-use model download, while the daily server used local-only Whisper and rejected uncached requests. Cache detection also accepted an incomplete model directory. | Setup now offers an explicit one-time download. The browser checks for model weights and gives the exact recovery command. Silent footage needs no model for the regular automatic path. |
| P0 | **FFmpeg discovery could fail even with FFmpeg installed.** `diagnostics.py` formed a WinGet glob with two adjacent asterisks. Python 3.12 rejected it when `LOCALAPPDATA` was set. | Corrected the pattern. The previously failing rerender tests passed after the change. |
| P0 | **FFmpeg failed when the project path contained an apostrophe.** Reproduced using a directory named `Editor's Media`. The absolute ASS path corrupted the filter expression. | The encoder runs from the output directory and references the generated subtitle file by its local filename. Input and output are passed as absolute command arguments. |
| P1 | **A current dependency quietly removed face-based framing.** Fresh installation selected OpenCV 5.0.0, which lacks the `CascadeClassifier` used here. OpenCV 4.14 exposes it. | Constrained OpenCV to the supported major version. Manual General clips now use the existing smart framing; full-frame profiles preserve the entire picture. |
| P1 | **Selection was hard to bypass in practice.** The browser had timestamp boxes, but source playback was limited to a special owner-reference workspace and the daily editor had no transcript search. | Added timestamped transcript search and a playable proxy from the chosen interval and audio stream. The user can choose the moment before spending time on a portrait render. |
| P1 | **Caption handling was inconsistent.** Automatic None could reuse matching cached words, and its saved job could require a transcript to rerender. A corrected SRT could be overwritten on the next placement/trim edit. Browser and rerender could look in different default cache directories. | None stays captionless. Corrections persist with source-relative timing and follow the trimmed interval. The browser passes its actual cache root. Whisper execution failure now reaches the job status explicitly in the daily flow. |
| P1 | **State and cancellation races.** An early cancellation could be discarded when the worker replaced its event. Completion could clear a new job's cancellation event. Restored media could also reuse an earlier browser cache key. | Retained the reserved event, paired completion with state cleanup, and versioned the browser preview using the artifact's media revision. |
| P1 | **Daily model isolation and local request validation had gaps.** Legacy editorial environment settings could enable a text-model call in the browser workflow. The listener checked Origin on writes but did not independently validate the Host. | The browser uses its existing heuristic selector. Optional legacy editorial calls stay on loopback and bypass environment proxy settings. The local browser server now requires a loopback Host and constrains artifact paths. |
| P1 | **A selection feature mixed source-relative and window-relative seconds.** Static intervals after the first source seconds could be scored as silent despite speech coverage. | Fixed the index calculation. The ranking remains a provisional activity score. |
| P2 | **The selector can miss the actual story.** Much of the score tracks motion and audio level. The opening score uses timing as a proxy. The existing project report's two confirmed anime moments were both missed by the baseline selector at its stated IoU threshold. The latest text-only playbook run accepted 24/32 scene outputs against a minimum of 28 plus attribution requirements. | The 2B playbook stays experimental. Use search and a human cut today. The two references cannot establish quality across podcasts, anime, news, or gameplay. |
| P2 | **Framing still has limits.** Haar face detection chooses a prominent face and wide compositions can fall back to contain. There is no speaking-face identity, split-screen control or per-shot crop editor. Hardcoded 30 fps can discard detail in 60 fps gameplay. Rotated phone, unusual pixel-aspect, HDR and interlaced sources need a dedicated media matrix. | Review the exported crop. Broadcast, gameplay and presentation preserve graphics. A manual framing control and a source-frame-rate option are follow-up work. |
| P2 | **Long recordings can strain memory and storage.** Transcription decodes the full audio stream to an in-memory float waveform. Local imports, previews, job versions and exports consume disk separately. A subsequent audio/language choice currently overwrites the source's one transcription cache file, so trim-only regeneration of an older unedited job may require rebuilding matching captions. | Current captions and video stay on disk. Planned improvements are a cache keyed by track and transcription task, chunked audio, and a user-visible storage view. |
| P2 | **Caption and export edge cases.** Some source subtitle tracks contain overlapping cues; current SRT validation assumes a linear non-overlapping stream. Audibly silent parts may still yield zero captions with a captioned mode. ASS style, font coverage, and platform overlay clearance vary by language, crop, and device. | Use Whisper or an intentional captionless interval if a source subtitle track fails. Review edited captions and the full portrait frame. Test Tamil, Tamil–English code switching and names with representative audio before making any accuracy claim. |
| P2 | **Persistence is per application process.** More than one server can share the cache and job folders. Job metadata, MP4, and SRT are separate files; rollback handles ordinary exceptions, but a power loss can still interrupt multi-file writes. The optional queue and desktop reviewer use different entry points and need native acceptance. | Use one Clipper instance per project. Independent backups and job versions help recover edits. Native Windows, CUDA, and VLC still need verification after these changes. |
| P2 | **Licensing documentation is incomplete for redistribution.** The repository has third-party notices and preserved playbook files but no top-level Clipper LICENSE at this baseline. | Personal operation and publishing one's own footage are separate from granting others software redistribution rights. The owner should choose a software license before presenting Clipper as licensed open source or distributing bundled software, weights or fonts. |

The rows describe findings from this review. They are not an exhaustive guarantee for every source format, runtime, or publishing scenario.

### Automate after measuring the current workflow

Use three to five recordings in one intended niche first. Save two or three human-selected, publishable intervals per recording with notes on the opening, required context, and ending. Split by complete recording when testing future algorithms. Compare the existing activity selector, a speech-boundary baseline, and optional local ranking on **recall among the first five suggestions**, **median endpoint error**, **editor keep rate**, and **minutes to export**. Keep crop and caption errors as separate measurements.

For a speech baseline, build intervals from actual timestamped sentences or pauses, deduplicate overlaps, and show the exact transcript excerpt. A future small model can rank a short list of stable interval IDs. Validate identifiers and ignore invalid or timed-out results while preserving manual cuts. Speech-first ranking belongs on podcasts and conversations; visual events and replays need visual or event-specific signals. Avoid another model upgrade before measuring that baseline.

## YouTube and source rights

- YouTube's [native Clips feature](https://support.google.com/youtube/answer/10332730) shares a 5–60 second excerpt linked to the original video. [Shorts remixing](https://support.google.com/youtube/answer/10623810) operates inside YouTube's supported workflow. A local exported MP4 is a different publishing action.
- The [YouTube Terms](https://www.youtube.com/t/terms) describe when downloading or using service content is authorized. For a local clip, use a file you recorded, a file supplied by the creator with permission, or appropriately licensed material/campaign footage. Check the footage, embedded music, license/campaign limits, attribution, and whether the intended account and platform are covered. [Whop’s campaign setup guide](https://whop.com/blog/set-up-content-rewards/) describes campaign-specific submission review. Follow the actual campaign rules.
- YouTube's [channel monetization policy](https://support.google.com/youtube/answer/1311392) applies reused-content and inauthentic-content rules at channel level. Permission, burned captions, vertical crops, and hook text do not on their own establish monetization eligibility. Original commentary or meaningful editorial contribution may be relevant. YouTube makes the eligibility decision.
- YouTube supports [Shorts up to three minutes](https://support.google.com/youtube/answer/15424877). A Short over one minute with an active Content ID claim is blocked globally. A shorter cut can still receive claims. The export uses the MP4/H.264/AAC family in [YouTube’s encoding guidance](https://support.google.com/youtube/answer/1722171); that guidance recommends preserving the recorded frame rate, whereas Clipper currently encodes at 30 fps.

## Verification

- Initial Linux run on the original Git revision: 317 passed, 8 failed, 13 skipped and 9 subtests passed. Failures included two FFmpeg discovery failures, a legacy test exposing cross-platform filename handling, and OS/display assumptions in native Windows/Tk tests.
- Patched Linux run: **320 passed, 18 skipped, 9 subtests passed**, with no failures. Skips include native platform/display requirements. Dependency, compilation, and Git whitespace checks passed.
- A Chromium end-to-end run used an original synthetic video with a synthetic English voice and a deliberately seeded timestamped transcript. It checked transcript search, selected-track preview playback, manual creation, a caption correction, a second rerender, persistence after reload, and exported delivery files. The repository's 15 Playwright regression checks also passed.
- The separate HTTP run checked partial-content playback, technical export validation, and the automatic captionless path with a pre-existing transcript. FFprobe confirmed the exported MP4 used 1080×1920 H.264 at 30 fps with AAC audio. Caption accuracy, subject framing on actual footage, and perceptual synchronization need evaluation on representative content.
- This environment could not reach the model host to download Whisper weights. These tests exercised cache reads and caption rendering. Live Whisper inference and the Windows/NVIDIA setup were not verified here. The failed model gate is historical evidence from this repository.
